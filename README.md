# Pikachu Volleyball RL

PPO self-play training and a desktop app to play against the trained AI in Pikachu Volleyball.

## Training algorithm

Training uses **Proximal Policy Optimization (PPO)** in a **self-play** setup. The policy and value function are **separate neural networks** (actor and critic), each a 256→256 MLP with Tanh activations — no shared backbone, so critic and policy gradients do not interfere as opponents evolve.

After an initial warm-up against a **random opponent**, the agent enters **league self-play**: each rollout samples an opponent from a pool of past checkpoints (prioritized fictitious self-play). The opponent runs with **frozen weights** (`eval()`, no gradient updates); only the learning agent's side is optimized.

Each PPO update follows the standard two-phase loop:

1. **Rollout** — parallel environments collect transitions (observations, actions, rewards, values, log-probs) using the current policy.
2. **Optimization** — for several epochs, the batch is shuffled and split into **minibatches**. Each minibatch updates:
   - **Policy loss** — clipped surrogate objective (limits how far the policy can move per update)
   - **Value loss** — MSE between predicted values and GAE returns
   - **Entropy bonus** — encourages exploration; coefficient **decays linearly** from 0.05 to 0.01 over training

A single policy controls both sides of the court (observations are mirrored for player 2). The trained actor is exported to ONNX for real-time inference in the desktop app.

## Requirements

- Python 3.12
- PyTorch (installed separately — GPU or CPU)
- Other dependencies are pinned in `requirements.txt` for reproducibility

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate

# PyTorch first (pick one)
pip install torch --index-url https://download.pytorch.org/whl/cu124   # GPU (CUDA 12.4)
# pip install torch --index-url https://download.pytorch.org/whl/cpu   # CPU only

pip install -r requirements.txt
```

## Train

```bash
python train.py
```

Saves checkpoints and the final model to `models/`:
- `models/pikachu_ppo_checkpoint_*.pth` — intermediate checkpoints
- `models/pikachu_ppo_final.pth` — final weights
- `models/pikachu_actor.onnx` — exported model for the desktop app

## Play (Human vs AI)

After training (or once `models/pikachu_actor.onnx` exists):

```bash
python app.py
```

### Controls

| Key | Action |
|-----|--------|
| Arrow keys | Move left/right, jump (up) |
| Space | Power hit |
| Space + Up | Lob (high arc) |
| Space + Down | Spike |
| Space + Left/Right | Horizontal power hit |
| D | Cycle difficulty (Easy / Medium / Hard / Impossible) |
| S | Switch sides |
| R | Restart |
| ESC | Quit |

### Difficulty levels

There is a single ONNX model; difficulty is adjusted via **temperature scaling** on the network's action logits (press **D** to cycle):

| Level | Temperature | Behavior |
|-------|-------------|----------|
| Easy | 3.0 | High noise — actions are nearly random |
| Medium | 1.5 | Moderate randomness — frequent mistakes |
| Hard | 0.5 | Low noise — mostly strong play (default) |
| Impossible | 0.0 | No sampling — always picks the highest-scoring action (`argmax`) |

Higher temperature flattens the probability distribution, so weaker moves are chosen more often. This mirrors PPO exploration at train time without needing separate checkpoints per level.

## Build desktop executable for Linux/WSL

Requires `models/pikachu_actor.onnx` (run training first or place the file in `models/`).

```bash
source .venv/bin/activate
pyinstaller pikachu_volleyball.spec
```

Output: `dist/PikachuVolleyball` (single binary, no Python needed on the target machine).

Run on Linux or WSL:

```bash
chmod +x dist/PikachuVolleyball   # once, if not executable
./dist/PikachuVolleyball
```

On WSL, you need a graphical session (WSLg on Windows 11, or an X server). The game opens in a pygame window — same controls as `python app.py`.

Bundle the executable via [GitHub Releases](https://docs.github.com/en/repositories/releasing-projects-on-github) rather than committing it to the repo.
